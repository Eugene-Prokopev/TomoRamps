1. ОБОРУДОВАНИЕ ПРОЕКТА
==================================================

Контроллер:

- Arduino Mega 2560
- RAMPS 1.6
- Marlin 2.1.2
- USB Serial, текущий порт обычно COM11
- скорость соединения: 250000 baud
- питание шаговых моторов: 12 В

Шаговые драйверы:

- оси X, Y, Z, A, B используют A4988 через RAMPS;
- ось C использует внешний TB6600;
- все моторы уже проверены через jog и работают;
- токи драйверов уже предварительно настроены;
- микрошаги драйверов уже выбраны пользователем.

Важно:
Python не генерирует STEP-импульсы самостоятельно.
Python отправляет G-code.
Marlin рассчитывает шаги и управляет STEP/DIR.

Архитектура:

Python GUI
    ↓
G-code через USB Serial
    ↓
Marlin
    ↓
STEP/DIR
    ↓
A4988 или TB6600
    ↓
шаговый двигатель

2. ФАКТИЧЕСКАЯ РАСКЛАДКА ОСЕЙ
==================================================

Физическая ось X:

- G-code: X
- назначение: точная ось X, микровинт
- драйвер: RAMPS X / A4988
- STEP: D54
- DIR: D55
- ENABLE: D38
- концевики:
  - X_MIN: D3
  - X_MAX: D2
- концевики NO:
  - COM → GND
  - NO → S
  - + не используется

Физическая ось Y:

- G-code: Y
- назначение: точная ось Y, микровинт
- драйвер: RAMPS Y / A4988
- STEP: D60
- DIR: D61
- ENABLE: D56
- концевики:
  - Y_MIN: D14
  - Y_MAX: D15

Грубая физическая ось X:

- в Marlin использует букву Z;
- в GUI должна называться:
  - `XX — грубый (Z)`
- назначение: грубая ось X, направляющая около 1 м
- драйвер: RAMPS Z / A4988
- STEP: D46
- DIR: D48
- ENABLE: D62
- концевики переназначены:
  - Z_MIN: D11
  - Z_MAX: D6

Точная физическая ось Z:

- в GUI должна называться:
  - `Z — точный (C)`
- G-code: C
- внутри Marlin это дополнительная ось, реализованная через внутренний драйвер K;
- драйвер: внешний TB6600
- STEP/PUL: D40
- DIR: D42
- ENABLE: D44
- концевики:
  - C_MIN/K_MIN: D18
  - C_MAX/K_MAX: D19
  - физически используются стандартные разъёмы RAMPS Z_MIN и Z_MAX

Подключение TB6600:

- D40 → PUL/STEP
- D42 → DIR
- D44 → ENA
- общий GND Arduino/RAMPS и TB6600 обязателен;
- мотор подключается к A+/A-/B+/B- TB6600;
- Python не управляет TB6600 напрямую.

Ось вращения образца:

- G-code: A
- GUI: `Вращение (A)`
- физически слот RAMPS E1
- драйвер A4988
- концевиков нет

Ось наклона:

- G-code: B
- GUI: `Наклон (B)`
- физически слот RAMPS E0
- драйвер A4988
- концевиков нет

Итоговый порядок осей в GUI:

1. X — точный (X)
2. Y — точный (Y)
3. Z — точный (C)
4. Вращение (A)
5. Наклон (B)
6. XX — грубый (Z)

Не перепутай порядок отображения GUI с буквами G-code.

==================================================
6. АЛГОРИТМ КАЛИБРОВКИ
==================================================

Для линейной оси:

1. Пользователь выбирает ось.
2. Программа показывает текущий steps/unit.
3. Программа читает фактическое значение из Marlin через M503.
4. Пользователь выбирает тестовое перемещение, например 10 мм.
5. Пользователь выбирает подачу, например 30 или 60.
6. Программа предупреждает, что движение будет реальным.
7. Пользователь нажимает кнопку «Обнулить».
8. Программа отправляет:
   
   ```gcode
   G92 X0
   ```

   или соответствующую ось.
9. Пользователь запускает тестовое перемещение.
10. Программа выполняет короткое безопасное перемещение выбранной оси.
11. Пользователь измеряет фактическое перемещение линейкой, штангелем или индикатором.
12. Пользователь вводит фактическое значение.
13. Программа рассчитывает новое значение:

   ```text
   new_steps =
   old_steps × commanded_distance / measured_distance
   ```

14. Программа показывает старое и новое значение.
15. Пользователь нажимает «Применить».
16. Программа отправляет:

   ```gcode
   M92 X<new_value>
   ```

17. Программа отправляет:

   ```gcode
   M500
   ```

18. Программа снова выполняет тестовое перемещение.
19. Пользователь подтверждает результат.
20. Значение записывается в calibration.json.

Для угловой оси A/B алгоритм такой же, но единицы — градусы:

```text
steps/degree =
old_steps × commanded_angle / measured_angle
```


- резервной копии;

- отсутствие другого выполняющегося движения.

Запрещать движение в сторону активного концевика.

Если во время теста сработал концевик:

1. прекратить новые команды;
2. отправить M410;
3. показать предупреждение;
4. не считать тест успешным;
5. предложить отъехать в обратном направлении.

Не запускать автоматический G28 для A/B, потому что у A/B нет концевиков.

Для C разрешать G28 только после подтверждения, что C_MIN и C_MAX физически подключены и проверены.

Не создавать очередь из множества перемещений.

==================================================
10. РАБОТА С M503
==================================================

Нужно реализовать парсер M503.

Он должен находить значения примерно такого вида:

```text
M92 X80.00 Y80.00 Z80.00 A80.00 B80.00 C80.00
```

или в нескольких строках.

Не предполагай, что порядок осей всегда одинаковый.

Если Marlin возвращает внутренние буквы I/J/K, сопоставь их с пользовательскими A/B/C согласно текущей конфигурации проекта:

```text
I → A
J → B
K → C
```

Если значение не найдено:

- показать ошибку;
- не менять JSON;
- не отправлять M92 автоматически.
